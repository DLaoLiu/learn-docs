# 事务相关面试题详解

## 1. MyBatis-Plus @DS注解导致的事务失效问题

### 项目中的实际场景
在用户行为分析平台中，我们使用MyBatis-Plus的@DS注解进行数据源切换：

```java
// Mapper层使用@DS注解切换数据源
@Mapper
public interface UserMapper extends BaseMapper<User> {
    // 默认使用主数据源
    int insertUser(User user);
    User selectById(Long id);
}

@DS("behavior")  // 切换到行为分析库
@Mapper  
public interface BehaviorAnalysisMapper extends BaseMapper<BehaviorAnalysis> {
    int insertBehaviorAnalysis(BehaviorAnalysis analysis);
    List<BehaviorAnalysis> selectByUserId(Long userId);
}

@DS("archive")  // 切换到历史归档库
@Mapper
public interface ArchiveMapper extends BaseMapper<ArchiveData> {
    int insertArchiveData(ArchiveData data);
}
```

### 问题分析：@DS注解的事务失效

```java
// ❌ 错误示例：事务无法跨数据源
@Service
public class UserAnalysisService {
    
    @Autowired
    private UserMapper userMapper;
    
    @Autowired  
    private BehaviorAnalysisMapper behaviorMapper;
    
    @Autowired
    private ArchiveMapper archiveMapper;
    
    @Transactional  // 这个事务只能管理默认数据源
    public void processUserAnalysis(UserAnalysisRequest request) {
        // 1. 主库操作 - 正常在事务中
        User user = new User();
        user.setName(request.getUserName());
        userMapper.insertUser(user);  // 主数据源，事务生效
        
        // 2. 行为库操作 - @DS切换数据源，脱离了原事务！
        BehaviorAnalysis analysis = new BehaviorAnalysis();
        analysis.setUserId(user.getId());
        behaviorMapper.insertBehaviorAnalysis(analysis);  // behavior数据源，事务失效！
        
        // 3. 归档库操作 - @DS切换数据源，同样脱离了原事务！
        ArchiveData archive = new ArchiveData();
        archive.setUserId(user.getId());
        archiveMapper.insertArchiveData(archive);  // archive数据源，事务失效！
        
        // 如果这里抛异常，只有userMapper的操作会回滚
        // behaviorMapper和archiveMapper的操作不会回滚！
        if (analysis.getScore() < 0) {
            throw new RuntimeException("分析失败");
        }
    }
}
```

@Configuration
public class DataSourceProxyConfig {
    
    @Bean
    @ConfigurationProperties(prefix = "spring.datasource.master")
    public DataSource masterDataSource() {
        return DruidDataSourceBuilder.create().build();
    }

    @Bean
    @ConfigurationProperties(prefix = "spring.datasource.archive")

        return DruidDataSourceBuilder.create().build();

    @Bean
    @Primary
    public DataSource dataSourceProxy() {

        targetDataSources.put("master", new DataSourceProxy(masterDataSource()));
        targetDataSources.put("behavior", new DataSourceProxy(behaviorDataSource()));
        targetDataSources.put("archive", new DataSourceProxy(archiveDataSource()));
        
        DynamicRoutingDataSource dynamicDataSource = new DynamicRoutingDataSource();
        dynamicDataSource.setTargetDataSources(targetDataSources);
        dynamicDataSource.setDefaultTargetDataSource(new DataSourceProxy(masterDataSource()));
        
        return dynamicDataSource;
    }
}

#### 1.3 使用@GlobalTransactional注解

```java
// ✅ 正确示例：使用Seata分布式事务
@Service
public class UserAnalysisService {
    
    @Autowired
    private UserMapper userMapper;
    
    @Autowired
    private BehaviorAnalysisMapper behaviorMapper; 
    
    @Autowired
    private ArchiveMapper archiveMapper;
    
    @GlobalTransactional(name = "user-analysis-tx", rollbackFor = Exception.class)
    public void processUserAnalysis(UserAnalysisRequest request) {
        try {
            // 1. 主库操作
            User user = new User();
            user.setName(request.getUserName());
            userMapper.insertUser(user);
            
            // 2. 行为库操作 - 通过@DS切换数据源，但在分布式事务中
            BehaviorAnalysis analysis = new BehaviorAnalysis();
            analysis.setUserId(user.getId());
            behaviorMapper.insertBehaviorAnalysis(analysis);
            
            // 3. 归档库操作 - 同样在分布式事务中
            ArchiveData archive = new ArchiveData();
            archive.setUserId(user.getId());
            archiveMapper.insertArchiveData(archive);
            
            // 4. 模拟业务异常
            if (analysis.getScore() < 0) {
                throw new RuntimeException("分析分数异常");
            }
            
            // 所有操作成功，分布式事务提交
            
        } catch (Exception e) {
            // 发生异常，所有数据源的操作都会回滚
            log.error("用户分析处理失败，开始回滚", e);
            throw e;
        }
    }
}
```

### 解决方案2：使用Redisson分布式锁 + 补偿机制

如果不想使用Seata，可以通过Redisson分布式锁实现补偿机制：

```java
@Configuration
public class RedissonConfig {
    
    @Bean
    public RedissonClient redissonClient() {
        Config config = new Config();
        config.useSingleServer()
              .setAddress("redis://127.0.0.1:6379")
              .setPassword("password");
        return Redisson.create(config);
    }
}

@Service
public class UserAnalysisService {
    
    @Autowired
    private RedissonClient redissonClient;
    
    @Autowired
    private UserMapper userMapper;
    
    @Autowired
    private BehaviorAnalysisMapper behaviorMapper;
    
    @Autowired
    private ArchiveMapper archiveMapper;
    
    public void processUserAnalysisWithCompensation(UserAnalysisRequest request) {
        String lockKey = "user_analysis_lock_" + request.getUserId();
        RLock lock = redissonClient.getLock(lockKey);
        
        Long userId = null;
        Long behaviorId = null;
        Long archiveId = null;
        
        try {
            // 获取分布式锁
            if (lock.tryLock(10, 30, TimeUnit.SECONDS)) {
                
                // 第一步：主库操作
                User user = new User();
                user.setName(request.getUserName());
                userMapper.insertUser(user);
                userId = user.getId();
                
                // 第二步：行为库操作
                BehaviorAnalysis analysis = new BehaviorAnalysis();
                analysis.setUserId(userId);
                behaviorMapper.insertBehaviorAnalysis(analysis);
                behaviorId = analysis.getId();
                
                // 第三步：归档库操作
                ArchiveData archive = new ArchiveData();
                archive.setUserId(userId);
                archiveMapper.insertArchiveData(archive);
                archiveId = archive.getId();
                
                // 模拟业务异常
                if (analysis.getScore() < 0) {
                    throw new RuntimeException("分析分数异常");
                }
                
            } else {
                throw new RuntimeException("获取分布式锁失败");
            }
            
        } catch (Exception e) {
            // 发生异常，执行补偿回滚
            compensateTransaction(userId, behaviorId, archiveId);
            throw new RuntimeException("用户分析处理失败", e);
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }
    
    /**
     * 补偿机制：手动回滚各个数据源的操作
     */
    private void compensateTransaction(Long userId, Long behaviorId, Long archiveId) {
        try {
            // 回滚归档库操作
            if (archiveId != null) {
                archiveMapper.deleteById(archiveId);
            }
        } catch (Exception e) {
            log.error("回滚归档数据失败", e);
        }
        
        try {
            // 回滚行为库操作  
            if (behaviorId != null) {
                behaviorMapper.deleteById(behaviorId);
            }
        } catch (Exception e) {
            log.error("回滚行为数据失败", e);
        }
        
        try {
            // 回滚主库操作
            if (userId != null) {
                userMapper.deleteById(userId);
            }
        } catch (Exception e) {
            log.error("回滚用户数据失败", e);
        }
    }
}
```

### 解决方案3：基于消息队列的最终一致性

```java
@Service
public class UserAnalysisService {
    
    @Autowired
    private UserMapper userMapper;
    
    @Autowired
    private RabbitTemplate rabbitTemplate;
    
    @Transactional  // 只管理主库事务
    public void processUserAnalysisAsync(UserAnalysisRequest request) {
        // 1. 主库操作在本地事务中
        User user = new User();
        user.setName(request.getUserName());
        userMapper.insertUser(user);
        
        // 2. 发送消息，异步处理其他数据源操作
        UserAnalysisEvent event = new UserAnalysisEvent();
        event.setUserId(user.getId());
        event.setUserName(user.getName());
        event.setAnalysisData(request.getAnalysisData());
        
        rabbitTemplate.convertAndSend("user.analysis.exchange", 
                                    "user.analysis.routing.key", 
                                    event);
    }
}

@RabbitListener(queues = "user.analysis.queue")
@Service
public class UserAnalysisEventHandler {
    
    @Autowired
    private BehaviorAnalysisMapper behaviorMapper;
    
    @Autowired
    private ArchiveMapper archiveMapper;
    
    @Autowired
    private UserMapper userMapper;
    
    public void handleUserAnalysisEvent(UserAnalysisEvent event) {
        try {
            // 处理行为库操作
            BehaviorAnalysis analysis = new BehaviorAnalysis();
            analysis.setUserId(event.getUserId());
            behaviorMapper.insertBehaviorAnalysis(analysis);
            
            // 处理归档库操作
            ArchiveData archive = new ArchiveData();
            archive.setUserId(event.getUserId());
            archiveMapper.insertArchiveData(archive);
            
        } catch (Exception e) {
            // 异步处理失败，可以实现重试机制或者补偿删除主库数据
            log.error("异步处理用户分析失败", e);
            
            // 补偿：删除主库中的用户数据
            try {
                userMapper.deleteById(event.getUserId());
            } catch (Exception compensateException) {
                log.error("补偿删除用户数据失败", compensateException);
                // 可以发送告警或者写入死信队列
            }
        }
    }
}
```

### 推荐方案选择

**对于你的项目场景，我推荐以下选择策略：**

1. **数据强一致性要求高**：使用Seata分布式事务（方案1）
2. **性能要求高，可接受最终一致性**：使用消息队列方案（方案3）
3. **简单场景，偶尔使用**：使用Redisson + 补偿机制（方案2）

在我们的大数据项目中，主要采用**消息队列 + 最终一致性**的方案，因为：
- 性能好，不会阻塞主流程
- 可靠性高，支持重试和死信队列
- 扩展性好，易于添加新的业务处理逻辑

## 3. 事务失效的常见场景

### 3.1 同类调用事务失效
```java
@Service
public class UserService {
    
    // 错误示例：同类方法调用，事务不生效
    public void updateUser(User user) {
        this.doUpdate(user); // 直接调用，事务失效
    }
    
    @Transactional
    public void doUpdate(User user) {
        userDao.update(user);
    }
    
    // 正确做法：通过ApplicationContext获取代理对象
    @Autowired
    private ApplicationContext applicationContext;
    
    public void updateUserCorrect(User user) {
        UserService proxy = applicationContext.getBean(UserService.class);
        proxy.doUpdate(user); // 通过代理调用，事务生效
    }
}
```

### 3.2 异常捕获导致事务不回滚
```java
@Transactional
public void processData() {
    try {
        userDao.insert(user);
        throw new RuntimeException("业务异常");
    } catch (Exception e) {
        // 捕获异常但不重新抛出，事务不会回滚
        log.error("处理失败", e);
    }
}

// 正确处理方式
@Transactional(rollbackFor = Exception.class)
public void processDataCorrect() {
    try {
        userDao.insert(user);
        businessService.process();
    } catch (BusinessException e) {
        // 手动标记回滚
        TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
        throw e;
    }
}
```

### 3.3 异步调用事务失效
```java
@Service
public class AsyncService {
    
    // 错误：异步方法中的事务失效
    @Async
    @Transactional
    public void asyncProcess() {
        // 异步线程中没有事务上下文
        userDao.update(user);
    }
    
    // 正确：在同步方法中完成事务操作
    @Transactional  
    public void syncProcess() {
        userDao.update(user);
        // 异步处理其他逻辑
        asyncService.doAsyncWork();
    }
}
```

## 4. 事务传播机制详解

### 常用传播行为
```java
// REQUIRED（默认）：加入当前事务，没有则创建新事务
@Transactional(propagation = Propagation.REQUIRED)

// REQUIRES_NEW：总是创建新事务，挂起当前事务
@Transactional(propagation = Propagation.REQUIRES_NEW)

// NESTED：嵌套事务，使用savepoint机制
@Transactional(propagation = Propagation.NESTED)

// NOT_SUPPORTED：以非事务方式执行，挂起当前事务
@Transactional(propagation = Propagation.NOT_SUPPORTED)
```

### 双事务场景示例
```java
@Service
public class OrderService {
    
    @Transactional
    public void createOrder(Order order) {
        orderDao.insert(order);
        
        // 调用REQUIRES_NEW方法，创建新事务
        logService.saveLog(order.getId());
        
        // 如果这里异常，order回滚，但log不会回滚
        if (order.getAmount() > 10000) {
            throw new RuntimeException("金额超限");
        }
    }
}

@Service  
public class LogService {
    
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void saveLog(Long orderId) {
        logDao.insert(new Log(orderId, "订单创建"));
    }
}
```

## 5. 常见面试问题与答案

### Q1：@Transactional注解失效的原因？
**答案：**
1. 同类方法直接调用（绕过代理）
2. 方法不是public的
3. 异常被捕获没有重新抛出
4. 数据库引擎不支持事务（如MyISAM）
5. 没有被Spring管理的类

### Q2：事务的隔离级别有哪些？
**答案：**
1. **READ_UNCOMMITTED**：读未提交，会出现脏读
2. **READ_COMMITTED**：读已提交，避免脏读，可能不可重复读
3. **REPEATABLE_READ**：可重复读（MySQL默认），避免脏读和不可重复读
4. **SERIALIZABLE**：串行化，最高隔离级别，性能最低

### Q3：如何解决分布式事务？
**答案：**
1. **2PC/3PC**：强一致性，但性能差，协调者单点故障
2. **TCC**：Try-Confirm-Cancel，业务侵入性强但可靠性高
3. **消息队列**：最终一致性，性能好，适合大多数场景
4. **Saga模式**：长事务拆分，每步都有对应补偿操作

### Q4：Spring事务的实现原理？
**答案：**
1. **AOP代理**：通过动态代理拦截方法调用
2. **TransactionManager**：统一的事务管理接口
3. **TransactionInfo**：保存事务信息和状态
4. **ThreadLocal**：保证事务信息的线程隔离
5. **连接管理**：确保同一线程使用同一数据库连接
